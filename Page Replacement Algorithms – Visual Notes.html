1. Basics (start here)

With virtual memory, a process need not be fully in RAM. Pages are brought in only when needed (demand paging). RAM has limited frames. When a needed page is not in any frame, a page fault occurs.

CPU needs page P
➜
P in frame?
YES → HIT
➜
NO → PAGE FAULT
OS loads P from disk
➜
Free frame? use it.
Else choose a victim (algorithm!)

Key terms

  • Reference string: the sequence of page numbers the CPU asks for.
  • Hit: page already in a frame. Fault (miss): page not in memory; very slow (disk).
  • Hit ratio = Hits ÷ Total references · Miss (fault) ratio = Faults ÷ Total references = 1 − Hit ratio.
  • Victim: the page removed to make room. Goal of every algorithm: minimise page faults.
  • Initially all frames are empty, so the first pages always cause faults (cold-start faults).
📚 Real life: Your study desk (RAM) holds only 3 books (frames). Your shelf (disk) holds hundreds. Needing a 4th book means putting one back – which one? That choice is the page-replacement algorithm.

2. Algorithms & Rules

🚪FIFO – First In First Out
Rule: Replace the page that has been in memory the longest (oldest loaded). Hits do NOT change order.
simpleBelady's anomaly
🎟️ Queue at a ticket counter – first person leaves first.
📚LIFO – Last In First Out
Rule: Replace the most recently loaded page (top of stack). Old pages stay forever.
poor
🥞 Stack of plates – the top plate is taken first.
🕒LRU – Least Recently Used
Rule: Replace the page not used for the longest time (look backwards). A hit refreshes the page.
goodno anomaly
📱 Phone's recent apps – the app you haven't opened for ages is closed first.
🔮Optimal (OPT)
Rule: Replace the page that will be used farthest in the future (look forward); a page never used again goes first.
best possiblenot implementable
🧳 Packing – leave behind what you'll need last. Needs future knowledge, so used only as a benchmark.
🔥MRU – Most Recently Used
Rule: Replace the page used most recently. Good for looping scans.
🔢LFU – Least Frequently Used
Rule: Replace the page with the smallest use count; tie → oldest loaded.

Tie-break & exam conventions

  • Frames start empty. Count every first load as a fault.
  • In OPT, if two pages are never used again, remove the one that was loaded earlier (leftmost frame).
  • Belady's anomaly: with FIFO, giving more frames can cause more faults. LRU and OPT are "stack algorithms" and never show it.
  • Fault order of quality (usually): OPT ≤ LRU ≤ FIFO.

    4. Types of Numericals (and how to solve each)

    Type 1 – Count page faults
    Given string + frames + algorithm. Draw the table, mark each column H/F, count F.
    Type 2 – Hit / miss ratio
    Hit ratio = hits ÷ n. For the classic string (n = 20) with FIFO: faults 15, hits 5 → hit ratio = 5/20 = 0.25 (25%), miss ratio = 0.75.
    Type 3 – Compare algorithms
    Run the same string through all algorithms and compare fault counts. Press Compare in section 5.
    Type 4 – Change the number of frames
    Same string, frames 1…7. Faults normally fall as frames grow.
    Type 5 – Belady's anomaly
    String 1 2 3 4 1 2 5 1 2 3 4 5 with FIFO: 3 frames → 9 faults, 4 frames → 10 faults!
    Type 6 – Effective Access Time
    EAT = (1 − p)·ma + p·(page-fault time). Solved in section 6.
    Type 7 – LIFO / MRU / LFU
    Same table method, different victim rule. Try them in the simulator and read the reason in each line.

    5-step exam method

    1. Write the reference string in a row.
    2. Draw one row per frame, all empty.
    3. For each page: if present, write H (nothing changes; for LRU note the usage).
    4. If absent, write F: use a free frame or apply the victim rule and write the reason.
    5. Count F and H; compute ratios.

    5. Compare all algorithms & Belady's anomaly

    Uses the reference string typed in section 3. Rows = algorithm, columns = number of frames (page faults). ⚠ red = faults increased with more frames (Belady's anomaly).

    6. Effective Access Time (EAT) – numerical

    p = page-fault rate (0…1), ma = memory access time, fault service time = time to fetch from disk. EAT = (1 − p) × ma + p × fault time.

    Solved: ma = 200 ns, fault time = 8 ms (= 8,000,000 ns), p = 1/1000.
    Line 1: (1 − 0.001) × 200 = 199.8 ns
    Line 2: 0.001 × 8,000,000 = 8000 ns
    Line 3: EAT = 199.8 + 8000 = 8199.8 ns (≈ 41× slower!)
    For only 10% slowdown (EAT ≤ 220): 200 + p × (8,000,000 − 200) ≤ 220 → p ≤ 20 / 7,999,800 ≈ 2.5 × 10⁻⁶ (about 1 fault per 400,000 accesses).
